# 桌面端扫码登录（纯 H5/公众号内）— API 对接说明

本文说明 **桌面应用** 如何调用后端接口，配合 **公众号内 H5 授权页** 完成扫码登录。

---

## 1. 基础约定

### 1.1 请求地址

与小程序/H5 一致：在站点根路径下访问 API。

```text
{API_BASE}/api/{path}
```

示例（以实际部署域名为准）：

```text
https://你的域名/api/user.desktopauth/createTicket
```

小程序里配置的 `websiteUrl` + `/api/` + 路径，即为桌面端应使用的同一套后端地址。

### 1.2 必填公共参数

所有接口均需携带 **`app_id`**（与前端 `config.js` 中的 `app_id` 相同，整数）。  
可放在 **Query** 或 **表单/Body** 中，与现有小程序请求方式保持一致即可。

| 参数    | 类型   | 说明           |
|---------|--------|----------------|
| `app_id` | int   | 应用 ID |

### 1.3 统一响应结构

成功时一般为：

```json
{
  "code": 1,
  "msg": "success 或 提示文案",
  "data": { }
}
```

业务失败时：

```json
{
  "code": 0,
  "msg": "错误说明",
  "data": { }
}
```

未登录、鉴权失败等场景可能返回 `code: -1`（与前端全局处理一致）。桌面端 `createTicket` / `poll` / `verifyToken` **不需要**用户 `token`。

---

## 2. 完整流程（桌面侧）

1. 桌面调 **创建票据**，拿到 `ticket`、`qrcode_url`、`expires_in`。  
2. 用 **`qrcode_url`** 生成二维码并展示给用户（推荐做法）。  
3. 用户用 **微信扫一扫** 扫码后，直接打开公众号内 H5 授权页（URL 自带 `ticket`）。  
4. H5 授权页 **加载时** 会调用 **`opened`**（无需登录）：票据从 `pending` 变为 `opened`，桌面端轮询可提示「已扫码，等待授权」。  
5. H5 授权页会先校验用户是否登录：未登录则先走公众号网页登录授权登录，登录成功后回跳到该授权页（`onShow` 会再次上报 `opened`，避免漏记）。  
6. 用户先点击「授权登录」：后端执行 `confirm`，票据状态变为 `authorized`（桌面端应反馈“已授权，待确认”）。  
7. 用户再点击「我知道了」：后端执行 `complete`，此时才会颁发桌面端 `token`；H5 页面随后应使用 `reLaunch` 跳转首页（不要使用 `navigateBack`）。  
8. 用户点击「取消」时，H5 授权页会调用 `cancel`，并跳转回首页。  
9. 桌面端对同一 `ticket` **轮询** **poll**：  
   - 过期后收到 `expired`，二维码 UI 必须显示“已失效/请刷新”；  
   - 收到 `cancelled`，应提示“用户已取消授权”；  
   - 收到 `opened`，可提示「已扫码，请等待用户在手机上点击授权」；  
   - 收到 `authorized`，应提示“已授权，等待用户确认”；  
   - 收到 `confirmed` 才读取 `token` 并完成登录。  
10. 桌面本地保存 `token`（及可选 `user_id`），后续调用 **verifyToken** 校验是否有效。  
11. 登录成功后 **立即停止轮询**。

## 3. 接口列表

### 3.1 创建登录票据

**用途**：开始一次扫码登录，生成短时票据与二维码链接。

| 项目   | 说明 |
|--------|------|
| 路径   | `user.desktopauth/createTicket` |
| 方法   | `POST`（推荐）或 `GET`，与 ThinkPHP 路由一致即可 |
| 鉴权   | 不需要用户 `token` |

**请求参数**（除公共 `app_id` 外无其它必填）：

| 参数     | 必填 | 说明        |
|----------|------|-------------|
| `app_id` | 是   | 应用 ID     |

**成功时 `data` 示例**：

```json
{
  "ticket": "a1b2c3d4e5f6...共32位十六进制小写",
  "expires_in": 300,
  "qrcode_url": "https://你的域名/h5/#/pages/my/desktop-login-auth/desktop-login-auth?ticket=a1b2c3d4e5f6..."
}
```

| 字段           | 说明 |
|----------------|------|
| `ticket`       | 票据 ID，轮询时使用 |
| `expires_in`   | 有效秒数，当前为 **300**（5 分钟） |
| `qrcode_url`   | **推荐**桌面端用该链接生成二维码：微信扫一扫可直接打开授权页并携带 `ticket` |

**说明**：同一 IP 在短时间内创建次数过多会返回错误（防刷），文案类似「请求过于频繁，请稍后再试」。

---

### 3.2 已打开授权页（已扫码反馈）

**用途**：用户扫码进入 H5 授权页后，由页面 **自动** 调用，将票据从 `pending` 置为 `opened`，供桌面端 `poll` 展示「已扫码」类提示。**不需要**用户登录态。

| 项目 | 说明 |
|------|------|
| 路径 | `user.desktopauth/opened` |
| 方法 | `GET`（参数放 Query 即可） |
| 鉴权 | 不需要用户 `token` |

**请求参数**：

| 参数     | 必填 | 说明 |
|----------|------|------|
| `app_id` | 是   | 应用 ID |
| `ticket` | 是   | 与二维码 URL 中一致 |

**成功时 `data`**：

```json
{ "status": "opened" }
```

若票据已不存在或已过期，返回 `data.status` 为 `expired`（与 `poll` 语义一致）。若票据已是 `authorized` / `confirmed` 等，则返回 **当前** `status`，不回退状态。

**说明**：桌面端 **无需** 调用本接口；仅 H5 授权页使用。

---

### 3.3 轮询票据状态（获取桌面 token）

**用途**：在手机确认前为 `pending`，确认后首次成功返回 `token` 与 `user_id`。

| 项目 | 说明 |
|------|------|
| 路径 | `user.desktopauth/poll` |
| 方法 | `GET` 推荐（参数放 Query） |
| 鉴权 | 不需要用户 `token` |

**请求参数**：

| 参数     | 必填 | 说明 |
|----------|------|------|
| `app_id` | 是   | 应用 ID |
| `ticket` | 是   | 创建接口返回的 32 位 hex，**小写** |

**响应 `data.status` 取值**：

| status      | 含义 |
|-------------|------|
| `pending`   | 尚未打开授权页（或 H5 尚未成功上报 `opened`） |
| `opened`    | 用户已打开 H5 授权页（已扫码），等待点击「授权登录」 |
| `authorized`| 用户已点击「授权登录」，等待点击「我知道了」 |
| `cancelled` | 用户在授权页点击了“取消” |
| `confirmed` | 已授权；**仅第一次**会同时返回 `token`、`user_id` |
| `expired`   | 票据不存在或已过期 |
| `consumed`  | token 已被取走（再次轮询不会出现第二个 token） |

**`confirmed` 时 `data` 示例**：

```json
{
  "status": "confirmed",
  "token": "桌面登录令牌，字符串",
  "user_id": 12345
}
```

**桌面端建议**：

- 每 **1～3 秒** 请求一次；总时长不要超过 `expires_in`，超时则提示用户刷新二维码并重新 `createTicket`。  
- 一旦 `status === 'confirmed'` 且拿到 `token`，**清除定时器，停止轮询**。  
- 若先收到 `confirmed` 但未带 `token`（理论上仅重复轮询时），按已消费处理即可。

---

### 3.4 取消授权（点击“取消”）

**用途**：H5 授权页点击“取消”后调用，后端将票据置为 `cancelled`，供桌面端轮询感知并同步提示。

| 项目 | 说明 |
|------|------|
| 路径 | `user.desktopauth/cancel` |
| 方法 | `POST` |
| 鉴权 | 需要用户 `token` |

**请求参数**：

| 参数     | 必填 | 说明 |
|----------|------|------|
| `app_id` | 是   | 应用 ID |
| `token`  | 是   | 用户登录态 token |
| `ticket` | 是   | 票据 |

---

### 3.5 完成授权（点击“我知道了”）

**用途**：H5 授权页点击“我知道了”后调用；只有此接口成功后，后端才会颁发桌面 token。

| 项目 | 说明 |
|------|------|
| 路径 | `user.desktopauth/complete` |
| 方法 | `POST` |
| 鉴权 | 需要用户 `token` |

**请求参数**：

| 参数     | 必填 | 说明 |
|----------|------|------|
| `app_id` | 是   | 应用 ID |
| `token`  | 是   | 用户登录态 token |
| `ticket` | 是   | 票据 |
| `agree`  | 是   | 固定传 `1` |

---

### 3.6 校验桌面 token（可选）

**用途**：启动时或调用业务接口前，确认本地保存的桌面 `token` 仍有效，并换取基础用户信息。

| 项目 | 说明 |
|------|------|
| 路径 | `user.desktopauth/verifyToken` |
| 方法 | `GET` 或 `POST` |
| 鉴权 | 不需要用户 `token`；传桌面专用 `token` |

**请求参数**：

| 参数     | 必填 | 说明 |
|----------|------|------|
| `app_id` | 是   | 应用 ID |
| `token`  | 是   | 轮询 `poll` 返回的桌面 `token` |

**成功时 `data`**：

```json
{
  "user_id": 12345,
  "nickName": "张三",
  "avatarUrl": "https://.../avatar.png"
}
```

**失败**：`code: 0`，`msg` 如「登录已失效」——桌面应清空本地 token，回到扫码登录。

桌面 token 在服务端缓存 **30 天**（与实现一致，若以后变更以服务端为准）。

---

> 说明：`user.desktopauth/opened`、`user.desktopauth/confirm`、`user.desktopauth/complete`、`user.desktopauth/cancel` 均由 H5 授权页调用；桌面端无需调用。

## 6. 与现有业务 API 的关系

当前实现中，桌面 `token` 在缓存中的键与小程序会话 `token` **相互独立**。  
若其它业务接口仍只认小程序端的 `token` 参数，需要在后端为「桌面客户端」单独做鉴权（例如根据 `desktop_auth:` 前缀解析 `user_id`），本说明不替代该部分开发。

## 8. 前后端职责拆分（完整）

### 8.1 桌面端职责

- 调用 `createTicket` 获取 `ticket / expires_in / qrcode_url`
- 使用 `qrcode_url` 生成二维码并显示倒计时
- 按固定频率轮询 `poll`
- 根据 `status` 做 UI 反馈：
  - `pending`：等待用户扫码或打开 H5
  - `opened`：已扫码进入授权页，等待用户点击「授权登录」
  - `authorized`：用户已授权登录，等待点击“我知道了”
  - `cancelled`：用户取消授权
  - `expired`：二维码过期
  - `consumed`：token 已被桌面取走后的重复轮询；应提示用户刷新并重新 `createTicket`
  - `confirmed`：获取 `token`，登录成功
- 仅在 `confirmed` 时保存 token，随后停止轮询

### 8.2 H5 授权页职责

- 从 URL 提取 `ticket`
- `onLoad` / `onShow`（微信内）静默请求 `opened`，上报「已打开页」
- 检查微信环境与用户登录态
- 未登录：调用统一登录模块 `doLogin()`，登录后回跳
- 已登录：
  - 点击“授权登录” -> 调用 `confirm`
  - 点击“我知道了” -> 调用 `complete`
  - 点击“取消” -> 调用 `cancel`
- `complete` / `cancel` 后统一 `reLaunch('/pages/tabBar/home/index')`

### 8.3 后端职责

- 创建短时票据并限流
- 提供轮询状态机输出
- 处理 `opened`（页面进入）与 `confirm / complete / cancel` 用户行为
- 仅在 `complete` 时签发桌面 token
- 提供 `verifyToken` 返回 `user_id / nickName / avatarUrl`

## 9. 后端状态机（票据生命周期）

票据缓存键：`desktop_login:{ticket}`

状态流转：

1. `pending`（创建后初始状态）
2. `opened`（H5 授权页调用 `opened`，用户已扫码进入页面）
3. `authorized`（用户点击“授权登录”）
4. `confirmed`（用户点击“我知道了”，已签发 token）
5. `consumed`（桌面端首次取走 token 后）

异常/中断状态：

- `cancelled`（用户点击取消）
- `expired`（缓存过期或票据不存在）

非法流转会被拒绝，例如：

- `pending` / `opened` 之外状态再次 `confirm`
- `authorized` 之外状态调用 `complete`
- `confirmed/consumed` 后再 `cancel`

## 10. 技术实现细节（后端）

### 10.1 缓存键与有效期

- 票据：`desktop_login:{ticket}`，TTL = `300s`
- 桌面 token：`desktop_auth:{token}`，TTL = `30天`
- 创建限流：`desktop_login_create:{ip}`（60s 窗口）
- 轮询限流：`desktop_login_poll:{ticket}:{ip}`（60s 窗口）

### 10.2 安全校验

- `ticket` 必须匹配正则：`^[a-f0-9]{32}$`
- 所有写操作校验 `app_id` 一致性
- `opened` 不要求用户 `token`（仅校验 `app_id` 与 `ticket`）
- `confirm/complete/cancel` 均要求用户登录态（`token`）
- `confirm/complete` 强制 `agree=1`
- 使用 `check_ld` 防重复点击

### 10.3 token 签发时机（关键）

- `confirm`：不签发 token，仅将状态置为 `authorized`
- `complete`：签发桌面 token，并将状态置为 `confirmed`
- `poll`：仅在 `confirmed` 首次返回 token，随后置 `consumed`

## 11. 技术实现细节（前端）

### 11.1 授权页核心逻辑

文件：`pages/my/desktop-login-auth/desktop-login-auth.vue`

- `onLoad`：读取 URL 中 `ticket`，若有则静默请求 `opened`
- `onShow`：微信内再次 `opened`；若未登录，走 `doLogin()`；已登录进入授权流程
- `confirmByUser`：调用 `user.desktopauth/confirm`
- `finishAck`：调用 `user.desktopauth/complete`
- `cancelAuth`：调用 `user.desktopauth/cancel`
- `complete/cancel` 后都 `reLaunch` 到首页

### 11.2 统一登录模块接入点

- 使用公共方法 `doLogin()`（定义于 `common/function.js`）
- 微信 H5 环境下会跳公众号 OAuth 登录并回跳当前页面

## 12. 联调与验收清单

### 12.1 正常链路

1. 桌面创建票据成功，二维码正常显示
2. 微信扫码进入授权页后，桌面 `poll` 可先收到 `opened`（再收到后续状态）
3. 未登录时自动跳登录；登录回跳后仍可收到 `opened`（幂等）
4. 点击“授权登录”，桌面收到 `authorized`
5. 点击“我知道了”，桌面收到 `confirmed + token`
6. 桌面保存 token 并停止轮询

### 12.2 异常链路

- 二维码过期：桌面收到 `expired` 并展示失效
- 用户取消：桌面收到 `cancelled`
- 重复点击：后端防连点生效，不产生重复签发
- 已消费 token 重复轮询：返回 `consumed`

### 12.3 verifyToken 验收

- 使用 `confirmed` 后拿到的 token 调 `verifyToken`
- 返回字段包含：
  - `user_id`
  - `nickName`
  - `avatarUrl`

## 13. 风险与建议

- 桌面端轮询 UI 必须覆盖所有状态，避免“无反馈”
- 公众号域名与 OAuth 回跳需保持一致，避免跳转异常
- 建议后续补充审计日志（create/confirm/complete/cancel/poll）
- 建议桌面端支持“刷新二维码”一键重建票据

文档版本与上述实现保持一致；若接口有变更，请同步更新本文。

## 14. ClawX 桌面应用（Electron）实现说明

本节描述 **本仓库** 内已落地的行为：业务仍走站点 `user.desktopauth/*`，由 Electron 主进程 **Host HTTP API** 代理给渲染进程，便于与 Vite 前端同源调用、统一鉴权与代理。

### 14.1 与文档 3.x 的差异（调用路径）

| 文档中的接口 | ClawX 渲染进程调用 | 主进程实际转发 |
|--------------|-------------------|----------------|
| `user.desktopauth/createTicket` | `POST /api/desktop-auth/create-ticket`（JSON body 可为 `{}`） | `POST` 表单 `app_id` → 站点 `createTicket` |
| `user.desktopauth/poll` | `POST /api/desktop-auth/poll`（JSON：`{ "ticket": "..." }`） | `POST` 表单 `app_id` + `ticket` → 站点 `poll` |
| `user.desktopauth/verifyToken` | `POST /api/desktop-auth/session/verify` 等 | 表单带 `app_id` + 桌面 `token` |
| `user.desktopauth/logout` | `POST /api/desktop-auth/session/logout` | 可选；部分环境未实现时桌面仅清本地会话 |
| `user.desktopauth/cancel` | `POST /api/desktop-auth/session/cancel-ticket` | 关闭弹窗且仍有未完成 `ticket` 时由主进程调用，避免票据悬挂 |

说明：文档 3.2、3.3 中 **poll** 以 **GET + Query** 为例；ClawX 主进程统一使用 **POST + `application/x-www-form-urlencoded`** 与现有后端路由对齐，与桌面 JSON 封装是两层，不冲突。

### 14.2 环境变量

| 变量 | 含义 |
|------|------|
| `CLAWX_DESKTOP_AUTH_BASE_URL` | 站点 API 根（未配置时回落到应用内置官网域名） |
| `CLAWX_DESKTOP_AUTH_APP_ID` | 与 H5/小程序一致的 `app_id`（未配置时回落到默认 `10001`） |

### 14.3 一码登录弹窗（`opened` 与轮询 UI）

- **轮询间隔**：约 **2 秒**（落在文档建议的 1～3 秒范围内）。
- **`poll` 返回的 `status`**：完整支持文档中的 **`pending` / `opened` / `authorized` / `cancelled` / `confirmed` / `expired` / `consumed`**；若服务端返回 `code !== 1`，桌面映射为 **`error`** 并展示错误文案。
- **进行中态（`opened`、`authorized`）**：在二维码区域显示**较轻的半透明遮罩**与提示文案，**不**展示「点击刷新」，码仍可辨认，避免用户误以为必须重扫。
- **终态（`cancelled`、`expired`、`consumed`、`error`）**：强遮罩 + 明确文案 + **「点击刷新」** 以重新 `createTicket`。
- **`expires_in` 本地兜底**：创建票据后除轮询外，使用 `expires_in`（缺省 **300** 秒）启动本地定时器；到期即视为过期 UI，与 `poll` 返回 `expired` 对齐，避免轮询延迟导致界面仍显示可扫。
- **`confirmed`**：拿到 `token` 后调用 `session/verify` 写入本地会话，关闭弹窗并停止轮询。

### 14.4 关闭弹窗与 `cancel-ticket`

与文档 **3.4** 一致：用户在手机端取消由 H5 调 `cancel`。桌面侧额外约定：用户**直接关闭**一码登录弹窗时，若仍持有未完成 `ticket`，主进程会调用 **`session/cancel-ticket`** 转发后端 `cancel`，减少无效轮询与票据悬挂（与 H5 取消互为补充场景）。
